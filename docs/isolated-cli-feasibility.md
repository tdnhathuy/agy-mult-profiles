# Isolated-file CLI auth feasibility (mock-only; blocked)

**Decision: do not enable an isolated-file backend.** Preserve the existing global `agyp.lock`/`KeychainGuard` transactions. The tests in `tests/isolated_cli_feasibility_test.rs` use a shell mock and fake token strings; they prove only that independent fake HOME directories, SSH environment variables, and `--gemini_dir` arguments can be arranged, mock processes can overlap and independently rewrite fake files, and the existing lock and private-file helpers behave as tested. They do **not** prove that `agy` authenticates from that file, avoids Keychain, persists a refreshed token, or keeps its logs/sessions/daemon state private. No real authentication, credential reads, or Keychain mutation were attempted.

## Evidence and gap

- Installed `agy --version` reports **1.2.16**. `agy --help` exposes no authentication backend selector; `--gemini_dir` is not listed in the CLI help. A read-only byte scan of the local executable found occurrences of `jetski-standalone-oauth-token`, `SSH_CONNECTION`, `SSH_CLIENT`, and `--gemini_dir`, but not their control flow. This is **not** evidence that the CLI selects the SSH/file-token path on macOS, or that it never falls back to Keychain.
- [Official installation/auth documentation](https://antigravity.google/docs/cli/install/) describes SSH authorization, not the CLI's token storage selection, refresh location, or strict no-Keychain fallback contract. The shipped CLI source/control flow was not available for inspection. ParaGravity at `d553e1815587c636ac9dae1bbf3ae274ea49b0ea` injects a fake SSH environment and isolated HOME for the desktop/language-server process, not the CLI. Its HOME setup may also link host Keychain state; its behavior cannot establish CLI isolation.
- `agyp` routes execution through `src/commands/exec.rs`, `prompt.rs`, and `task.rs`; they use the global `agyp.lock` and Keychain guards. Profile login/removal (`profile.rs`), quota (`quota.rs`), and usage (`usage.rs`) also use that global transaction lock. `build_agy_command` in `src/agy.rs` supplies `--gemini_dir` but leaves HOME unchanged. The experimental tests are intentionally outside all production execution paths.

## Next evidence required before implementing opt-in

Obtain authoritative CLI 1.2.16 source or a vendor-supported contract for the macOS SSH/file-token branch, including token read/write/refresh, refusal of Keychain fallback, state directories and daemon behavior. Then run a separately approved, controlled live-auth isolation experiment with two dedicated non-production identities and instrumented Keychain access (without printing tokens), checking concurrent start, profile-specific refresh and persistence, same-profile lock, failure/timeout and no cross-account fallback. The current mock tests cannot substitute for that proof. Do not offer `--auth-backend isolated-file` until this is resolved.
