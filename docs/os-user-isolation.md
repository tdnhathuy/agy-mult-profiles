# Opt-in macOS OS-user isolation (MacBook only; live verification pending)

`agyp exec profile` remains the legacy global-Keychain transaction unless explicitly bound. A bound profile runs with a separate local UID, its own home, and that user's GUI bootstrap namespace via `/usr/bin/sudo -H -u USER -- /bin/launchctl asuser UID /absolute/agy …`. Bound executions use a per-profile lock rather than the global Keychain lock. Other agyp commands are **not** isolated; use `exec` for this workflow. No profile token is copied to another home. Binding does not enroll OAuth or create an account.

1. On the MacBook, create **two separate standard local macOS users** via System Settings → Users & Groups (not this CLI). Log into each account in a GUI session, unlock its login Keychain, install/authorize agy as that user and complete OAuth through its own browser/UI. Never paste codes or credentials into agyp or chat. Keep both GUI sessions active with Fast User Switching.
2. Install a trusted `agy` executable in a root-owned, non-group/world-writable absolute path whose parent directories are also root-owned and non-group/world-writable. For example, a system-managed `/opt/homebrew/bin/agy` qualifies only if its resolved executable and **every ancestor** meet these checks; a user-owned `~/.local/bin/agy` will be rejected. Ensure the binary is available in the invoking user's PATH. `sudo` must permit the invoking account to switch to both local users and may prompt interactively. Do not add `NOPASSWD` casually.
3. Register profiles as usual (`agyp login profile-1`, `agyp login profile-2` if needed), then bind: `agyp isolate bind profile-1 --user alice`; `agyp isolate bind profile-2 --user bob`; inspect with `agyp isolate status`. Each must be a different UID, neither the invoking UID. Existing profiles' legacy credentials are not moved or deleted.
4. In two MacBook terminals, run `agyp exec profile-1 -- --version` and `agyp exec profile-2 -- --version` as a smoke test, then run actual agy commands concurrently. Confirm the account identity/auth for each through its own UI; do not print token material. A failed sudo, missing GUI session, changed identity/home, unsafe directory or unsafe executable fails closed rather than using the shared Keychain. `agyp isolate unbind profile-1` returns that profile to **legacy shared-Keychain** execution; do not unbind as a workaround for an isolated failure.

Caveats: `sudo` alone does not create or unlock a login Keychain; `launchctl asuser` enters an existing GUI bootstrap but may not satisfy every version of agy's Keychain/OAuth behavior. A successful `--version` does **not** prove auth separation. Test real authentication on the MacBook, including concurrent distinct-account operations and repeat access after relogin. No real macOS account switching or agy OAuth was performed on the development host. The target user's `.gemini` directory, if present, must be user-owned and private (0700-equivalent). Standard macOS homes often have world-readable mode; the check prohibits group/world **write**, not read.
